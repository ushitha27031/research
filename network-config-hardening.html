Cisco configuration hardening

Final-year research project by Ushitha Samudaya

AI-generated network configurations often work but leave devices open: Telnet, plaintext passwords, unused services. This tool asks a fine-tuned model to harden a Cisco configuration, checks its answer line by line, and scores the result with the method from the thesis. See how this tool connects to the model.

What happens in one run

  1. The page calls /health. If nobody has used the model for 15 minutes, Modal has shut the container down to save cost, so it starts a new one on an L40S GPU and vLLM loads the model. This cold start takes a few minutes; later requests are answered straight away.
  2. The page sends your configuration with the same system prompt and format the model was trained on. Settings: temperature 0 (always the model's most likely answer), up to 2,500 output tokens, repetition penalty 1.15.
  3. vLLM runs the base model with your adapter applied and returns the answer as Markdown.
  4. Back in the browser, the validator cleans and completes the answer, the scoring rates it, and the corrected configuration is highlighted. Your configuration is sent only to your Modal endpoint.
